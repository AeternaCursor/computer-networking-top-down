# P1 · 手写 HTTP 全家桶：服务器 + 客户端 + 反向代理

> 对应章节：第 2 章（应用层、套接字编程）。三个角色全用裸 socket 手写，共约 100 行。

## 1. 现象

三个程序在本机搭出一座微型互联网：

```
浏览器 ──> proxy.py(8002 反向代理) ──> server.py(8001 后端)
client.py(手写客户端) ──────────────────┘
```

- 浏览器访问 8002，端出 8001 后厨做的菜——客人全程不知后厨存在
- `curl.exe -v` 拿到完整对话：`>` 请求行/头，`<` 状态行/头/正文
- 杀掉后厨再访问：前台不倒，回 **502 Bad Gateway**

## 2. 矛盾

- 一台机器一个 IP 怎么开多家店？→ **端口 Port**（0~65535）
- 客人要的菜怎么区分？→ 解析**请求行** `GET /路径 HTTP/1.1`，按路径分发
- 后厨挂了前台凭什么陪葬？→ 代理必须**容错**，失败要给客人交代（502）

## 3. 设计（术语对照）

| 术语 | 人话 |
|---|---|
| Socket 套接字 | 电话线 |
| bind / listen | 占门牌 / 坐窗口等客 |
| accept / connect | 开门接客（三次握手完成点）/ 出门敲门 |
| Request Line 请求行 | `GET /about HTTP/1.1` = "来份 about" |
| Status Code 状态码 | 200 有货 / 404 没这道菜 / 502 后厨失联 |
| Reverse Proxy 反向代理 | 前台店：对客人是店，对后厨是客（Nginx 的本职） |
| Forward Proxy 正向代理 | 替客人出门的跑腿（Clash 的本职） |

## 4. 实现

- **server.py**：v1 固定响应 → v2 解析请求行分发 `/`、`/about`、404 → v3 加 `settimeout` 防卡死 + try/except 保店门常开
- **client.py**：`create_connection`（内含 DNS 解析 + 三次握手）→ 发请求 → `recv` 循环读到空（对方 `Connection: close` 挂断即收完）
- **proxy.py**：接客人原话**一字不改**转给后厨（无为），后厨失联时 `except OSError` 回 502（后手），`finally` 关连接

## 5. 验证：错误全家福（本篇核心战利品）

| 术语 | 谁回的话 | 实测方式 |
|---|---|---|
| `Connection Refused`（秒拒） | **操作系统** | 端口改 8001 后访问 8000；店没开时启动 client |
| `404 Not Found` | **后端代码** | 访问未知路径 |
| `502 Bad Gateway` | **代理代码** | 杀掉 server.py 后经 proxy 访问 |
| `Connection Timed Out` | 没人 | P0 的 GitHub 实测（SYN 丢失 + RTO 重传） |

排障第一刀永远是：**报错来自哪一层？**

踩坑记录（真实事故）：浏览器并发预连接 + 单线程后厨 = 后厨被一条空连接卡死，前台连锁超时崩溃。教训：**服务端每条连接必须设超时，代理必须有异常兜底**——这正是 Nginx 工业级与玩具的分界线。

## 6. 升华

- 浏览器、curl、手写 client，说的是同一套话——协议即普通话
- 反向代理的进阶形态：多家后厨轮班（**负载均衡 Load Balancing**）、常点菜品冷藏（**缓存 Cache**）——Nginx 的两大主业
- 遗留：并发（同时接待多客需多线程/异步，P5 后再战）；keep-alive 长连接复用
